# 제출 문서

이 문서는 과제 검토자가 로컬 실행, 체험 계정, 구현 범위, 테스트 방법, QA 증적을 빠르게 확인하기 위한 제출용 요약입니다.

## 1. 실행 요약

루트 경로에서 Docker Compose를 실행합니다.

```bash
docker compose -f service/infra/docker-compose.yml up --build
```

접속 주소:

| 항목 | 주소 |
| --- | --- |
| Client | http://localhost:5173 |
| Server | http://localhost:8080 |
| Health check | http://localhost:8080/api/health |

선택적으로 `.env.example`을 복사해 로컬 환경값을 바꿀 수 있습니다.

```bash
cp .env.example .env
```

`.env`는 git에 커밋하지 않습니다. 외부 API 키나 운영 비밀값은 저장하지 않습니다.

## 2. 체험 계정

첫 화면은 심사용 선택형 로그인입니다. 실제 비밀번호 인증 대신 사용자를 선택하면 해당 사용자의 id가 `X-Member-Id`로 API에 전달됩니다.

| 구분 | 이름 | id | 확인 포인트 |
| --- | --- | --- | --- |
| 일반 사용자 | 류성열 | `1` | 대부분의 Lv1/Lv2 기능을 확인하기 좋은 기본 사용자 |
| 일반 사용자 | 여자친구 | `2` | 다른 구성원 관점의 편지, 방 참여, 멤버 권한 확인 |
| 일반 사용자 | 아버지 | `3` | 가족방 구성원 관점 확인 |
| 일반 사용자 | 지훈 | `4` | 프로젝트방 구성원 관점 확인 |
| 운영자 | 운영자 | `100` | 전체 책 주문 조회, CSV, 상태 변경, 취소 처리 확인 |

## 3. 주요 QA 흐름

일반 사용자:

1. 사용자 선택 화면에서 `류성열` 선택
2. 방 관리 대시보드에서 참여 방, 초대받은 방, 방 생성 확인
3. 방에 진입해 채팅, 추억 게시판, 미션 인증, 편지 확인
4. 메인 페이지의 전체 기록 캘린더에서 월 이동과 날짜별 기록 요약 확인
5. `추억을 책으로 소장 > 책 만들기`에서 방, 상품, 기간, 콘텐츠, 미리보기, 주문 요청 흐름 확인
6. `주문 상태`, `주문 내역`에서 테이블, 필터, CSV, 상세 모달 확인

운영자:

1. 사용자 선택 화면에서 `운영자` 선택
2. 책 주문 관리 화면에서 전체 주문 20건 seed 확인
3. 주문일, 상태, 검색, 정렬, 표시 개수, 페이지 이동 확인
4. 전체/필터링/선택한 데이터 CSV 다운로드 확인
5. 주문 행 클릭으로 상세 모달 확인
6. 진행 가능한 주문의 다음 상태 변경과 취소 처리 확인

## 4. 구현 범위

Lv1:

- 체험 사용자 선택 기반 진입
- 기록방 생성, 초대, 참여, 방 관리 대시보드
- 방장/멤버 권한에 따른 방 나가기와 삭제 보호 흐름
- polling 기반 채팅
- 사진 업로드 기반 추억 게시판과 댓글
- 미션 인증, 승인/동의, 댓글
- 1:1 비공개 편지
- 전체 기록 캘린더
- 프로필과 알림 설정

Lv2:

- 전역 메뉴 `추억을 책으로 소장`
- 상품 안내, 책 만들기, 주문 상태, 주문 내역
- 방 1개 선택 후 상품, 기간, 콘텐츠를 고르는 책 제작 흐름
- `PHOTOBOOK_A4_SC`, `PHOTOBOOK_A5_SC`, `SQUAREBOOK_HC` 상품 3종
- 템플릿 기반 미리보기와 로컬 예상 견적
- 주문 생성, 진행/이력 조회, 취소
- 운영자 주문 관리, 상세 조회, 상태 변경, CSV 다운로드

Lv3:

- 사용자/운영자 선택 화면 안내 강화
- 방 관리 대시보드와 사이드바 depth 정리
- 홈 화면 참여 기록방 요약과 캘린더 월/연도 이동 개선
- 주문 테이블, 상세 모달, CSV 네이밍, 페이지네이션 등 UI/UX 개선
- 모바일 대응과 최종 E2E는 별도 Lv3 이슈에서 최종 검증

## 5. 책 주문 기능 정책

창작 방식은 `TEMPLATE`로 고정합니다. 사용자가 PDF를 직접 업로드하거나 템플릿과 PDF를 혼합하는 방식은 이번 구현 범위에서 제외했습니다.

| 항목 | 구현 내용 |
| --- | --- |
| 상품 | 로컬 DB seed 기반 상품 3종 |
| 콘텐츠 입력 | 기록방의 추억, 미션, 편지, 채팅 데이터를 템플릿에 바인딩 |
| 페이지 계산 | 콘텐츠 타입, 사진 수, 댓글 수, 메시지 수 기반 산정 |
| 미리보기 | 실제 PDF가 아닌 템플릿 기반 화면 미리보기 |
| 견적 | 로컬 가격 정책 기반 mock 견적 |
| 주문 | 로컬 DB에 주문과 선택 콘텐츠 스냅샷 저장 |
| 상태 | 운영자 화면에서 로컬 상태 전이 |

제외 범위:

- 실제 외부 Book Print API 호출
- PDF 직접 업로드
- 혼합 제작 방식
- 실결제, 실환불, 실배송
- 예치금 모델
- 외부 웹훅

## 6. 테스트 명령

프론트엔드 빌드:

```bash
cd service/client
npm ci
npm run build
```

백엔드 테스트:

```bash
cd service/server
./gradlew test
```

API smoke test:

```bash
curl -s http://localhost:8080/api/health
curl -s -H "X-Member-Id: 1" http://localhost:8080/api/book-archive/products
curl -s -H "X-Member-Id: 1" http://localhost:8080/api/book-archive/orders/status
curl -s -H "X-Member-Id: 100" http://localhost:8080/api/operator/book-orders
```

## 8. 제한 사항

- 과제 검증용 선택형 로그인이라 실제 인증/인가 시스템은 아닙니다.
- 채팅은 WebSocket이 아니라 polling 기반입니다.
- 업로드 파일은 로컬 파일 시스템에 저장됩니다.
- 책 미리보기는 실제 인쇄용 PDF가 아니라 템플릿 기반 화면 표현입니다.
- 책 주문, 견적, 상태 변경은 외부 연동 없이 로컬 DB에서 처리합니다.
- 운영자 화면은 MVP 수준이며 실제 운영 감사 로그, 결제 승인, 배송 추적까지 포함하지 않습니다.

## 9. 제출 전 점검

- README만 보고 Docker 실행이 가능한지 확인
- 체험 사용자와 운영자 역할이 화면에서 직관적으로 구분되는지 확인
- Lv1/Lv2/Lv3 구현 범위 설명이 실제 서비스와 맞는지 확인
- 외부 API 키, 비밀번호, 회사 식별 문자열이 문서에 없는지 확인
- QA 증적 경로가 실제 파일 구조와 맞는지 확인
