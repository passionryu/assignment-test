화면 정의 원칙:

- Lv1의 방 중심 사이드바 계층을 유지한다.
- 일반 사용자 사이드바에 운영자 기능을 노출하지 않는다.
- 일반 사용자 사이드바에는 모든 방 목록 아래에 `추억을 책으로 소장` 전역 디렉토리 1개만 추가한다.
- `추억을 책으로 소장`은 특정 방의 하위 메뉴가 아니다.
- `추억을 책으로 소장`을 펼치면 `상품 안내`, `책 만들기`, `주문 상태`, `주문 내역` 순서로 하위 메뉴가 열린다.
- `상품 안내`는 별도 페이지로 분리하되 상세 화면 기획은 아직 확정하지 않고 기획중으로 둔다.
- 책 만들기는 반드시 방 1개 선택에서 시작한다. 여러 방을 한 권에 섞지 않는다.
- 방 선택 후 상품을 먼저 선택하고, 선택 상품의 페이지 범위가 이후 콘텐츠 선택 제한의 기준이 된다.
- 상품 선택 후 기간을 고르면 해당 기간의 추억 게시글, 미션 인증, 편지가 자동으로 불러와진다.
- 자동 불러온 콘텐츠에서 사용자가 제외할 항목은 빼고, 다른 기간의 항목은 별도 추가로 가져올 수 있다.
- 예상 페이지 수가 선택 상품의 페이지 범위를 벗어나면 다음 단계로 진행하지 못하게 막는다.
- 창작 방식은 `TEMPLATE`로 고정하고 사용자가 다른 방식을 선택하지 않는다.
- 실제 PDF 생성, PDF 업로드, 실결제, 실배송, 예치금, 웹훅은 Lv2 구현 범위에서 제외한다.
- 운영자 화면은 고정 체험 사용자 중 `운영자` 캐릭터를 선택했을 때만 진입하는 과제 검증용 MVP다.

## SCREEN-004 상품 안내 - 기획중

목적:

- `추억을 책으로 소장` 하위에 상품 안내를 별도 페이지로 둔다.
- 사용자가 책 만들기 전에 상품 3종의 차이를 이해할 수 있는 진입점을 마련한다.

상태:

- 이 화면은 별도 페이지로 분리하는 것만 확정한다.
- 상세 구성, 비교 항목, 추천 문구, CTA 배치는 아직 기획중이다.
- 구현자는 이 화면을 확정 스펙으로 보지 말고 후속 기획 승인 후 상세 구현한다.

임시 표시 문구:

```text
상품 안내
상품별 상세 안내는 기획중입니다.
책 만들기에서는 선택한 방 기준으로 상품을 다시 선택합니다.
```

## SCREEN-005 전역 책 보관 메뉴/방 선택

목적:

- Lv1의 방 중심 사이드바를 해치지 않고 책 주문 기능을 사이드바 하단의 전역 메뉴로 묶는다.
- 책을 만들기 전에 어떤 방의 기록을 책으로 만들지 1개만 선택하게 한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 사이드바 상위 메뉴 | 모든 방 목록 아래의 전역 `추억을 책으로 소장` |
| 사이드바 하위 메뉴 | `상품 안내`, `책 만들기`, `주문 상태`, `주문 내역` |
| 운영자 기능 | 일반 사용자 사이드바에서는 미노출 |
| 방 선택 카드 | 방 이름, 방 타입, 멤버 수, 최근 기록 수 |
| 선택 제한 | 책 1권당 방 1개만 선택 |
| 주요 액션 | `다음: 상품 선택` |

상태/검증 문구:

| 상태 | 문구 |
| --- | --- |
| 방 미선택 | 책으로 만들 방을 1개 선택해 주세요. |
| 방 없음 | 책으로 만들 수 있는 참여 방이 없습니다. |
| 여러 방 선택 시도 | 책 1권에는 하나의 방 기록만 담을 수 있습니다. |
| 권한 오류 | 참여 중인 방의 기록만 책으로 만들 수 있습니다. |

UX 기준:

- 기존 방 하위의 채팅, 추억 게시판, 미션 인증, 편지 메뉴와 분리해 모든 방 목록 아래에 책 메뉴를 배치한다.
- `상품 안내`, `책 만들기`, `주문 상태`, `주문 내역`을 좌측 최상위에 각각 노출하지 않는다.
- 진행 중 주문은 `주문 상태`, 완료/취소/오류 주문은 `주문 내역`에서 처리한다.
- 운영자 기능은 사용자 선택 화면의 운영자 캐릭터 진입으로 분리한다.

## SCREEN-006 상품 선택 및 책 설정

목적:

- 선택한 방의 기록을 어떤 물리 상품으로 만들지 먼저 결정한다.
- 상품 선택으로 이후 페이지 제한을 확정한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 선택 방 요약 | 방 이름, 방 타입, 기록 보유 기간 |
| 책 제목 | 기본값 예: `우리 둘의 100일 기록` |
| 상품 카드 | A4 소프트커버 포토북, A5 소프트커버 포토북, 고화질 스퀘어북 하드커버 |
| 상품 코드 | `PHOTOBOOK_A4_SC`, `PHOTOBOOK_A5_SC`, `SQUAREBOOK_HC` |
| 상품 스펙 | 크기, 커버, 제본, 페이지 범위 |
| 추천 배지 | 방 기록 특성 기준 사진 많음, 텍스트 많음, 선물/보관 적합 |
| 수량 | 기본 1권, 변경 시 견적에 반영 |
| 주요 액션 | `다음: 기간 선택` |

상품별 페이지 범위:

| 상품 | 페이지 범위 |
| --- | --- |
| A4 소프트커버 포토북 | 24~130p |
| A5 소프트커버 포토북 | 50~200p |
| 고화질 스퀘어북 하드커버 | 24~130p |

상태/검증 문구:

| 상태 | 문구 |
| --- | --- |
| 상품 미선택 | 상품을 선택해 주세요. |
| 제목 없음 | 책 제목을 입력해 주세요. |
| 제목 길이 초과 | 책 제목은 40자 이하로 입력해 주세요. |
| 지원하지 않는 상품 | 선택할 수 없는 상품입니다. |

## SCREEN-007 기간 선택/콘텐츠 자동 불러오기

목적:

- 선택한 방과 상품을 기준으로 책에 담을 기록의 기본 기간을 선택하게 한다.
- 기간 선택 직후 해당 기간의 추억 게시글, 미션 인증, 편지를 자동으로 불러온다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 선택 방/상품 요약 | 방 이름, 상품명, 페이지 범위 |
| 기간 프리셋 | 최근 1개월, 최근 3개월, 전체, 직접 선택 |
| 직접 기간 | 시작일, 종료일 |
| 자동 불러오기 결과 | 추억 게시글 n개, 미션 인증 n개, 편지 n개 |
| 선택 제외 콘텐츠 | 채팅은 기본 자동 로드 제외 |
| 주요 액션 | `자동 구성 확인` |

상태/검증 문구:

| 상태 | 문구 |
| --- | --- |
| 기간 미선택 | 기록을 가져올 기간을 선택해 주세요. |
| 기간 오류 | 시작일은 종료일보다 늦을 수 없습니다. |
| 콘텐츠 없음 | 선택한 기간에 책으로 만들 기록이 없습니다. |
| 자동 로드 성공 | 선택 기간의 기록을 불러왔습니다. |

UX 기준:

- 사용자가 처음부터 모든 콘텐츠를 수동으로 고르게 하지 않는다.
- 기간 선택을 기본값으로 삼고, 이후 커스텀 단계에서 빼고 더하게 한다.
- 채팅은 분량 폭이 크므로 자동 포함하지 않고 별도 추가 옵션으로 둔다.

## SCREEN-008 콘텐츠 커스텀/페이지 제한

목적:

- 자동 불러온 콘텐츠에서 뺄 것은 빼고, 다른 기간의 콘텐츠를 추가해 책 구성을 조정하게 한다.
- 선택 상품의 페이지 제한을 넘으면 다음 단계로 진행하지 못하게 한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 자동 포함 콘텐츠 | 기간 기준으로 불러온 추억, 미션, 편지 |
| 제외 액션 | 포함된 콘텐츠 체크 해제 |
| 다른 기간에서 추가 | 날짜/타입 검색 후 항목 추가 |
| 채팅 추가 | 선택 시 날짜 범위 단위로 추가 |
| 페이지 미터 | 현재 예상 페이지 수 / 상품 최소~최대 페이지 수 |
| 제한 경고 | 최소 미달, 최대 초과, 정상 범위 |
| 주요 액션 | `미리보기 만들기` |

상태/검증 문구:

| 상태 | 문구 |
| --- | --- |
| 최소 페이지 미달 | 선택한 상품은 최소 페이지 수를 채워야 합니다. 기록을 더 추가해 주세요. |
| 최대 페이지 초과 | 선택한 상품의 최대 페이지 수를 넘었습니다. 일부 기록을 제외해 주세요. |
| 정상 범위 | 선택한 상품의 페이지 범위 안에 있습니다. |
| 추가 검색 결과 없음 | 해당 기간에 추가할 수 있는 기록이 없습니다. |

UX 기준:

- 페이지 제한은 상품 선택 이후부터 계속 고정 기준으로 보여준다.
- 페이지 제한 초과 시 `미리보기 만들기` 버튼을 비활성화한다.
- 제한을 맞추기 위한 제안 문구를 제공한다.

## SCREEN-009 책 미리보기/견적

목적:

- 주문 요청 전 사용자가 책의 구성과 예상 결과를 이해하게 한다.
- 실제 PDF 생성이 아니라 템플릿 기반 mock 미리보기임을 명확히 한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 책 구성 | 표지, 목차, 추억 페이지, 미션 페이지, 편지 페이지, 선택 채팅 페이지 |
| 대표 페이지 | 표지, 추억 대표 페이지, 미션 인증 페이지, 편지 페이지, 선택 채팅 요약 페이지 |
| 예상 페이지 수 | 선택 상품의 페이지 범위 안인지 표시 |
| mock 견적 | 기본가, 추가 페이지 금액, 수량, 배송비, 예상 합계 |
| 상품 요약 | 선택 상품명과 코드 |
| 주요 액션 | `이 구성으로 주문 요청` |
| 보조 액션 | `기록 다시 조정`, `상품 변경` |

상태/검증 문구:

| 상태 | 문구 |
| --- | --- |
| 미리보기 생성 중 | 선택한 기록을 템플릿에 배치하는 중입니다. |
| 생성 실패 | 미리보기를 만들지 못했습니다. 선택 기록을 다시 확인해 주세요. |
| 견적 안내 | mock 견적은 실제 결제가 아닌 주문 요청 검토용입니다. |
| 페이지 수 안내 | 예상 페이지 수는 선택한 사진과 글 분량에 따라 달라질 수 있습니다. |

## SCREEN-010 주문 요청 확인

목적:

- 사용자가 결제 없이 주문 요청만 생성한다는 점을 확인하게 한다.
- 주문 생성 시 선택 방, 상품, 기간, 콘텐츠, 견적 정보가 스냅샷으로 저장된다는 점을 명확히 한다.

처리 방식:

- 책 미리보기 화면 위에 dim overlay와 확인 모달을 표시한다.
- 모달을 닫으면 미리보기 화면으로 돌아간다.

모달 문구:

```text
주문 요청을 만들까요?
선택한 방, 기록, 상품 정보로 운영자 검토용 주문 요청이 생성됩니다.
실제 결제와 배송은 진행되지 않습니다.

[취소] [주문 요청]
```

검증 문구:

| 상태 | 문구 |
| --- | --- |
| 미리보기 없음 | 주문 요청 전 미리보기를 먼저 생성해 주세요. |
| 페이지 제한 오류 | 선택 상품의 페이지 범위를 맞춘 뒤 주문 요청을 진행해 주세요. |
| 중복 요청 | 이미 생성된 주문 요청입니다. 주문 목록에서 상태를 확인해 주세요. |
| 생성 실패 | 주문 요청을 만들지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 성공 | 주문 요청이 생성되었습니다. |

## SCREEN-011 주문 상태/주문 내역

목적:

- 일반 사용자가 전역 `추억을 책으로 소장` 하위에서 자신의 진행 중 주문과 과거 주문을 확인하게 한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 사이드바 위치 | `추억을 책으로 소장 > 주문 상태`, `추억을 책으로 소장 > 주문 내역` |
| 주문 상태 | 진행 중 주문의 현재 상태와 타임라인 |
| 주문 내역 | 완료/취소/오류 주문 목록 |
| 주문 상세 | 주문 당시 방, 상품, 기간, 콘텐츠, 견적 스냅샷 |
| 빈 상태 CTA | `책 만들기` |

상태 문구:

| 상태 | 문구 |
| --- | --- |
| 진행 주문 없음 | 진행 중인 책 주문이 없습니다. |
| 주문 내역 없음 | 아직 만든 책 주문이 없어요. |
| 조회 실패 | 주문 정보를 불러오지 못했습니다. |
| 권한 오류 | 내 주문만 확인할 수 있습니다. |

## SCREEN-012 운영자 캐릭터 진입/주문 목록

목적:

- 운영자 기능을 일반 사용자 사이드바에서 분리한다.
- 고정 체험 사용자 선택 화면에서 운영자 캐릭터를 선택했을 때만 운영자 주문 확인 화면으로 진입한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 체험 사용자 선택 | 일반 사용자 4명 + 운영자 캐릭터 |
| 운영자 진입 안내 | 운영자 캐릭터는 주문 상태 검증용 |
| 주문 테이블 | 주문번호, 사용자, 방 이름, 책 제목, 상품, 상태, 생성일 |
| 필터 | 상태, 상품, 생성일 |
| 검색 | 주문번호, 사용자 이름, 방 이름 |
| 주요 액션 | 주문 상세 보기 |

상태 문구:

| 상태 | 문구 |
| --- | --- |
| 빈 상태 | 확인할 주문이 없습니다. |
| 로딩 | 전체 주문을 불러오는 중입니다. |
| 오류 | 운영자 주문 목록을 불러오지 못했습니다. |

## SCREEN-013 운영자 주문 상세/상태 변경

목적:

- 운영자가 주문 내용을 검토하고 허용된 상태 전이 또는 취소 처리를 수행하게 한다.

주요 구성:

| 영역 | 내용 |
| --- | --- |
| 주문 상세 | 사용자, 방, 상품, 기간, 선택 콘텐츠, 예상 페이지 수, mock 견적 |
| 미리보기 | 대표 페이지와 구성 요약 |
| 상태 변경 | 다음 상태 변경 버튼, 변경 메모 |
| 취소 처리 | 취소 사유 입력, 취소 버튼 |
| 이력 | 상태 변경자, 변경 시각, 변경 전/후 상태, 메모 |

상태 전이:

| 현재 상태 | 허용 액션 |
| --- | --- |
| `PAID` | `PDF_READY`, `CANCELLED_REFUND` |
| `PDF_READY` | `CONFIRMED`, `CANCELLED_REFUND` |
| `CONFIRMED` | `IN_PRODUCTION` |
| `IN_PRODUCTION` | `PRODUCTION_COMPLETE` |
| `PRODUCTION_COMPLETE` | `SHIPPED` |
| `SHIPPED` | `DELIVERED` |
| `DELIVERED` | 변경 불가 |
| `CANCELLED_REFUND` | 변경 불가 |
| `ERROR` | 운영자 검토 후 별도 처리 |

검증 문구:

| 상태 | 문구 |
| --- | --- |
| 허용되지 않는 전이 | 현재 상태에서는 선택한 상태로 변경할 수 없습니다. |
| 취소 사유 없음 | 취소 사유를 입력해 주세요. |
| 종료 상태 변경 | 이미 완료 또는 취소된 주문은 다시 변경할 수 없습니다. |
| 변경 성공 | 주문 상태가 변경되었습니다. |
| 취소 성공 | 주문이 취소 처리되었습니다. |

## 범위

이 문서는 Lv2 책 제작/주문 기능의 사용자 화면과 과제용 운영자 주문 확인 화면을 정의한다.

Lv2는 실제 인쇄 운영 시스템이 아니다. 사용자가 방 1개를 선택하고, 상품을 고른 뒤, 기간 기준으로 기록을 자동 불러오고, 필요한 콘텐츠를 커스텀하여, 상품별 페이지 제한 안에서 mock 견적 기반 주문 요청을 생성하는 업무 흐름을 검증 가능하게 만드는 것이 목표다.
