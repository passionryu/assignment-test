# Issue #8 코드리뷰 에이전트 코드 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| API 범위 | PASS | #8 범위인 목록, 작성, 날짜 구분, 검색/이동에 집중했다. |
| 서비스 흐름 | PASS | `ChatService`에서 회원 확인, 방 접근 검증, 메시지 저장, AI 응답 저장 흐름이 보인다. |
| 책임 분리 | PASS | GPT 호출 경계는 `ChatAssistantClient`, DB 조회/저장은 `ChatRepository`로 분리했다. |
| 날짜 구분 | PASS | 응답의 `occurredDate`를 기준으로 프론트에서 날짜 구분선을 렌더링한다. |
| 검색 이동 | PASS | 검색 결과의 `messageId`를 DOM id로 연결해 해당 메시지 위치로 이동한다. |
| fallback | PASS | API key가 없거나 외부 호출 실패 시 채팅 저장은 유지하고 AI 응답만 fallback 처리한다. |

## 수용한 설계 결정

- 실시간 WebSocket은 #8 MVP 범위에서 제외하고 REST 기반으로 구현했다.
- AI 응답은 `기록방 AI` 시드 멤버를 sender로 저장한다.
- 실제 OpenAI key가 없는 로컬 환경에서도 시연이 끊기지 않게 fallback 응답을 제공한다.
- 검색은 선택한 방 안에서만 수행한다.

## 잔여 리스크

- 현재 인증은 기존 MVP와 동일하게 `X-Member-Id` 헤더 기반이다.
- 대화 삭제, 수정, 읽음 처리, 페이지네이션은 아직 구현하지 않았다.
- 실제 OpenAI 호출은 사용자가 `.env`에 key를 입력한 뒤 별도 확인이 필요하다.
