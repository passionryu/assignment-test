# Issue #10 보안 에이전트 보안 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| 방 접근 권한 | PASS | 모든 미션 API에서 방 참여 여부를 검증한다. |
| 미션 소속 검증 | PASS | 제출/동의 시 `roomId`와 `missionId` 소속을 함께 확인한다. |
| 인증 요청 소속 검증 | PASS | 동의 대상 제출이 현재 방의 미션에 속하는지 검증한다. |
| 자기 동의 차단 | PASS | 본인이 올린 인증 요청에는 동의할 수 없다. |
| 완료 상태 보호 | PASS | 완료된 미션에는 추가 제출/동의를 막는다. |
| 파일 타입 검증 | PASS | `image/*` MIME과 허용 확장자만 저장한다. |
| 파일 크기 제한 | PASS | 인증 이미지는 5MB 이하로 제한한다. |
| 파일명 보호 | PASS | 저장 파일명은 UUID 기반이며 원본 파일명을 그대로 사용하지 않는다. |
| Secret 관리 | PASS | API key, 비밀번호, 토큰 추가 없음. |
| 실패 로그 | PASS | 실패 맥락은 남기되 파일 내용과 본문 전문은 로그에 남기지 않는다. |

## 권한/데이터 보호 메모

- 미참여 회원은 미션 목록 조회, 미션 생성, 이미지 업로드, 인증 제출, 동의를 할 수 없다.
- 존재하지 않는 방/미션/제출은 명확한 404 계열 오류로 반환한다.
- 이미지 업로드 실패 로그에는 파일 크기와 식별 정보만 남기며 파일 내용은 기록하지 않는다.
- MVP 인증은 기존 정책대로 `X-Member-Id` 헤더 기반이다.

## 잔여 리스크

- 운영 환경에서는 인증/인가 레이어와 rate limit이 필요하다.
- 로컬 정적 파일 노출은 Lv1 검증용이며 운영에서는 스토리지 접근 제어를 재설계해야 한다.
- 이미지 바이너리 정밀 검사, EXIF 제거, 악성 파일 스캔은 후속 범위다.
- 동의 취소/반려가 추가되면 상태 전이 규칙과 감사 로그를 별도로 설계해야 한다.
