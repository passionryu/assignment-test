# Issue #10 코드리뷰 에이전트 코드 리뷰

| 빌드 | PASS | Backend compile, Frontend build 통과. |

## 수용한 설계 결정

- 기본 미션은 커플/가족/학급·동아리 방 타입별 20개씩 로컬 시드로 제공한다.
- 모든 기본 미션은 사진으로 인증 가능한 문장만 사용한다.
- 커스텀 미션은 방장만이 아니라 방 구성원 누구나 추가할 수 있다.
- 인증 요청은 사진 업로드 후 본문과 날짜를 함께 제출한다.
- 완료 미션에는 추가 인증 요청과 추가 동의를 막아 상태가 흔들리지 않게 한다.
- 로컬 업로드 파일은 `/uploads/missions/**` 정적 경로로 노출한다.

## 코드 관찰

- `MissionService`의 메인 흐름은 회원 확인 → 방 참여 검증 → 대상 미션/제출 검증 → 상태 변경 순서로 읽힌다.
- `MissionImageStorage`는 파일 타입, 확장자, 크기 검증을 담당하고 실패 로그를 남긴다.
- 실패 로그는 `who`, `what`, `requestData`, `reason` 형식으로 통일되어 있다.
- 로컬 시드는 과거 preset 미션 제출 찌꺼기를 정리해 데모 데이터가 섞이지 않도록 했다.

## 잔여 리스크

- 미션 수정/삭제는 이번 이슈 범위 밖이다.
- 동의 취소/반려는 이번 이슈 범위 밖이다.
- 서버 페이지네이션은 아직 없으며, 현재 미션 수는 방당 20개 규모를 기준으로 한다.
- 업로드 이미지 바이러스 스캔, 리사이징, CDN 전환은 운영 전환 시 후속 작업이다.
