# Issue #13 보안 에이전트 보안 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| 권한 검증 | PASS | 초대 생성은 방 `OWNER`에게만 허용한다. |
| 수신자 검증 | PASS | 초대 수락/거절 시 초대 대상 memberId/email/phoneNumber와 현재 회원을 대조한다. |
| 민감 정보 로그 | PASS | 이메일/전화번호는 실패 로그에서 마스킹한다. |
| 공개 저장소 secret | PASS | 새 secret, API key, webhook URL 추가 없음. |
| 입력 검증 | PASS | 방 이름, 방 타입, 초대 연락처, 이메일 형식을 검증한다. |
| 중복 요청 | PASS | 동일 방/동일 대상의 만료 전 대기 초대를 차단한다. |

## Secret Scan 메모

다음 항목은 기존 프로젝트의 더미/문서/필드명으로 판단했다.

- `assignment_password`: 로컬 Docker DB 더미 비밀번호
- `local-dummy-hash`: 로컬 시드용 더미 해시
- `password` 관련 DTO/필드/문서 표현
- `js-tokens`: npm package name

## 잔여 리스크

- 현재 MVP는 `X-Member-Id` 헤더 기반이므로 실제 서비스 전환 시 인증/인가 레이어가 필요하다.
- 초대 연락처는 회원 식별에 사용되므로 운영 환경에서는 rate limit과 감사 로그 정책이 추가되어야 한다.
