# Issue #9 코드리뷰 에이전트 코드 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| 요구 범위 | PASS | 게시글 목록, 상세, 작성, 이미지 URL 표시, 댓글 작성/조회 범위를 구현했다. |
| API 경계 | PASS | `/api/rooms/{roomId}/memories` 하위로 추억 게시판 API를 방 컨텍스트에 묶었다. |
| 서비스 흐름 | PASS | `MemoryService`에서 회원 검증, 방 참여 검증, 입력 검증, 저장, 응답 흐름이 순서대로 보인다. |
| Repository 분리 | PASS | QueryDSL 조회 책임과 JPA 저장 책임을 `MemoryRepository`에 모았다. |
| 프론트 연결 | PASS | 방 기능의 `추억 게시판` 메뉴에서 목록, 작성 폼, 상세, 댓글 패널이 동작한다. |
| 로컬 fallback | PASS | 서버 미응답 시 데모 추억 데이터로 화면 확인이 가능하다. |
| 빌드 | PASS | Backend compile, Frontend build 통과. |

## 수용한 설계 결정

- Lv1 범위에 맞춰 실제 파일 업로드는 제외하고 이미지 URL 입력만 지원한다.
- 게시글 작성 시 대표 이미지 URL이 없으면 이미지 placeholder를 보여준다.
- 댓글은 게시글 상세 패널 안에서 작성하고 즉시 반영한다.
- 추억 목록은 `occurredDate desc`, `createdAt desc`, `id desc` 기준으로 정렬한다.
- 방에 참여하지 않은 사용자는 게시글 목록, 상세, 작성, 댓글 작성을 할 수 없다.

## 코드 관찰

- `MemoryService`는 메인 use case 흐름을 유지하고 검증 책임을 private method로 분리했다.
- `MemoryRepository`의 public method에는 호출 목적을 설명하는 한국어 한 줄 주석이 있다.
- 실패 로그에는 `who`, `what`, `requestData`, `reason`이 포함된다.
- 기존 `memory_posts` 테이블과 새 `memory_comments` 엔티티를 사용해 콘텐츠 도메인 범위를 확장했다.

## 잔여 리스크

- 실제 이미지 업로드, 이미지 MIME/용량 검증, 썸네일 생성은 Lv1 범위 밖이다.
- 게시글 수정/삭제, 댓글 수정/삭제는 이번 이슈 범위 밖이다.
- 화면 정의서와 완전한 픽셀 일치는 Human QA에서 한 번 더 확인한다.
