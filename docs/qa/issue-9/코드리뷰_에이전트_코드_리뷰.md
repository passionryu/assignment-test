## 수용한 설계 결정

- 일반 사용자가 이미지 URL을 직접 입력하지 않도록 파일 선택/드래그앤드롭 기반 업로드로 변경한다.
- 업로드 파일은 로컬 `uploads/memories`에 저장하고 `/uploads/memories/**` 정적 경로로 노출한다.
- Docker 실행 시 업로드 파일이 컨테이너 재생성으로 바로 사라지지 않도록 `app-upload-data` volume을 사용한다.
- 추억 목록은 우선 클라이언트 페이지네이션으로 6개씩 보여준다.
- 댓글은 게시글 상세 패널 안에서 작성하고 즉시 반영한다.
- 추억 등록, 수정, 삭제 결과는 상단 문구가 아니라 모달로 안내한다.
- 추억 수정/삭제는 작성자 본인만 가능하게 제한한다.
- 추억 목록은 `occurredDate desc`, `createdAt desc`, `id desc` 기준으로 정렬한다.
- 방에 참여하지 않은 사용자는 게시글 목록, 상세, 작성, 이미지 업로드, 댓글 작성을 할 수 없다.

## 코드 관찰

- `MemoryService`는 메인 use case 흐름을 유지하고 업로드 저장 책임은 `MemoryImageStorage`로 분리했다.
- `MemoryImageStorage.storeImageSelectedByMember`에는 사용자가 URL을 직접 입력하지 않게 하는 의도가 한국어 주석으로 남아 있다.
- 실패 로그에는 `who`, `what`, `requestData`, `reason`이 포함된다.
- `.gitignore`에 업로드 디렉터리를 추가해 사용자가 올린 이미지가 GitHub에 커밋되지 않도록 했다.

## 잔여 리스크

- 썸네일 생성, 이미지 리사이징, 바이러스 스캔은 Lv1 범위 밖이다.
- 댓글 수정/삭제는 이번 이슈 범위 밖이다.
- 현재 페이지네이션은 클라이언트 기준이므로 게시글 수가 크게 늘면 서버 페이지네이션으로 전환해야 한다.
- 화면 정의서와 완전한 픽셀 일치는 Human QA에서 한 번 더 확인한다.
