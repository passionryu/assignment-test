# Issue #9 보안 에이전트 보안 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| 방 접근 권한 | PASS | 모든 추억 API에서 방 참여 여부를 먼저 검증한다. |
| 게시글 소속 검증 | PASS | 상세/댓글 작성 시 `roomId`와 `memoryId`를 함께 검증한다. |
| 입력 검증 | PASS | 제목, 본문, 이미지 URL, 댓글 길이와 blank 값을 검증한다. |
| 이미지 URL 제한 | PASS | `http://`, `https://`, `/`로 시작하는 URL만 허용한다. |
| Secret 관리 | PASS | 새 API key, 비밀번호, 토큰, webhook URL 추가 없음. |
| 실패 로그 | PASS | 실패 원인은 구조화된 로그 메시지에 남기되 본문 전문은 로그에 남기지 않는다. |

## 권한/데이터 보호 메모

- 참여하지 않은 방 접근은 `ROOM_ACCESS_DENIED`로 차단한다.
- 다른 방의 게시글 ID를 알고 있어도 현재 방 URL로 조회하면 `MEMORY_POST_NOT_FOUND`를 반환한다.
- 글 본문과 댓글 전문은 민감할 수 있으므로 검증 실패 로그에는 길이나 필드 상태만 남긴다.
- MVP 인증은 기존 프로젝트 정책대로 `X-Member-Id` 헤더 기반이며, 운영 전환 시 인증/인가 레이어가 필요하다.

## 잔여 리스크

- 이미지 URL은 외부 리소스를 직접 렌더링하므로 운영 환경에서는 allowlist, proxy, CSP 정책을 추가 검토해야 한다.
- 현재는 URL 문자열 검증만 수행하며 실제 이미지 파일 검증은 하지 않는다.
- rate limit, abuse 방지, 신고/차단 정책은 Lv1 범위 밖이다.
