# Issue #9 보안 에이전트 보안 리뷰

## 검토 결과

| 항목 | 결과 | 메모 |
|---|---|---|
| 방 접근 권한 | PASS | 모든 추억 API에서 방 참여 여부를 먼저 검증한다. |
| 게시글 소속 검증 | PASS | 상세/댓글 작성 시 `roomId`와 `memoryId`를 함께 검증한다. |
| 이미지 업로드 권한 | PASS | 이미지 업로드도 방 참여 여부 검증 이후에만 수행한다. |
| 파일 타입 검증 | PASS | `image/*` MIME과 허용 확장자만 저장한다. |
| 파일 크기 제한 | PASS | 업로드 이미지는 5MB 이하로 제한한다. |
| 파일명 보호 | PASS | 원본 파일명을 저장 파일명으로 사용하지 않고 UUID 기반 파일명으로 저장한다. |
| 업로드 경로 관리 | PASS | 업로드 디렉터리는 Git ignore와 Docker volume으로 관리한다. |
| Secret 관리 | PASS | 새 API key, 비밀번호, 토큰, webhook URL 추가 없음. |
| 실패 로그 | PASS | 실패 원인은 구조화된 로그 메시지에 남기되 본문 전문은 로그에 남기지 않는다. |

## 권한/데이터 보호 메모

- 참여하지 않은 방 접근은 `ROOM_ACCESS_DENIED`로 차단한다.
- 다른 방의 게시글 ID를 알고 있어도 현재 방 URL로 조회하면 `MEMORY_POST_NOT_FOUND`를 반환한다.
- 글 본문과 댓글 전문은 민감할 수 있으므로 검증 실패 로그에는 길이나 필드 상태만 남긴다.
- 파일 업로드 실패 로그에는 파일 크기와 방 ID만 남기고 원본 파일 경로나 파일 내용은 남기지 않는다.
- MVP 인증은 기존 프로젝트 정책대로 `X-Member-Id` 헤더 기반이며, 운영 전환 시 인증/인가 레이어가 필요하다.

## 잔여 리스크

- 업로드 이미지는 로컬 정적 파일로 노출되므로 운영 환경에서는 CDN, 접근 제어, 이미지 프록시 정책을 추가 검토해야 한다.
- 현재는 MIME/확장자/크기 기준 검증이며 이미지 바이너리 정밀 검사와 악성 파일 스캔은 하지 않는다.
- 업로드 파일 삭제, orphan 파일 정리, 사용자별 저장 용량 제한은 후속 범위다.
- rate limit, abuse 방지, 신고/차단 정책은 Lv1 범위 밖이다.
